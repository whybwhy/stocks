# /dd — 일일 목표가 이중 적재

## 실행 모드 분기 (**반드시 먼저 판별**)

| 사용자 표현 예 | 하는 일 |
|----------------|--------|
| `/dd` + 종목 블록 **만** 또는 `/dd …` 에 **갱신·반영·Supabase 적용** 요청이 **없음** | SQL 초안을 **채팅에 먼저 보여준 뒤**, 사용자 승인 후에만 `*_dual.sql` 파일을 생성·수정한다. **`price_alerts` / `price_alerts_log` 테이블에 실제 INSERT·REST 호출 금지.** |
| **「파일반영」「파일 반영」「저장해줘」** 등 **파일만** 반영 요청 *(갱신·Supabase 없음)* | 직전 미리보기(또는 같은 턴 종목 블록) 기준으로 `*_dual.sql` 생성·수정. Supabase·DB INSERT **금지.** |
| **「미리보기 없이」「바로 파일생성」「파일생성 + slug」** 등 — **미리보기·대기 생략** | 같은 턴 종목 블록(또는 직전 확정안)으로 **즉시** 4단계 파일 저장·slug 갱신(요청 시). Supabase **금지.** |
| **「slug 갱신」「슬러그 갱신」「공개 slug」** 등 *(종목 블록 없이 slug 만, 또는 파일 반영과 함께)* | **공개 slug 로테이션**(아래 절) 수행. 파일 반영과 동시 요청이면 `*_dual.sql` 저장과 함께 처리. |
| 동일 종목 블록에 대해 **「갱신해줘」「Supabase 에 반영」「DB 에 넣어줘」「실제 적용」** 등 **명시적인 DB 적재 의사**가 있음 *(같은 턴부터 직후 턴까지 이어져도 됨)* | (1) SQL 미리보기·승인으로 `*_dual.sql` 확정, (2) 그 SQL이 의미하는 **모든 행**을 순서대로 **`public.price_alerts`**(멱등)·**`public.price_alerts_log`** 에 **실제 적재**한다. |

- **`/dd {종목정보}`** 처럼 **블록만** 주고 **갱신 문구가 없으면 Supabase·DB에 적용하지 않는다.**
- **갱신 모드일 때만** `application-local.yml` 등 사용자 환경의 Supabase 설정을 사용할 수 있다. 적재 결과(성공 건수·SKIP·오류)를 짧게 요약한다.

## 파일 반영 순서 (**필수 — `/dd`·`/dd 수정` 공통**)

에이전트가 **스스로 SQL 파일을 바로 저장·덮어쓰지 않는다.** 아래 순서를 따른다.

| 단계 | 동작 |
|------|------|
| **1. 미리보기** | `INSERT` 초안을 채팅에 제시한다. 전체가 길면 **요약 표 + `price_alerts`·`price_alerts_log` 핵심 `VALUES` 일부** 또는 **변경 diff** 로 보여준다. |
| **2. 요약** | 배치일 `YYYYMMDD`·근거, `price_alerts`·`price_alerts_log` 행 수, 멱등 SKIP 예상, `### 미확정·미매칭 종목`, slug 변경 여부를 짧게 적는다. **채팅에 「예정 파일명」「예정 경로」 표현 금지** — 파일 미저장 시 경로를 말하지 않는다. |
| **3. 대기** | 사용자가 **파일 반영 트리거**(아래)를 보낼 때까지 **`Write`·`StrReplace`·`git mv`로 `src/main/resources/*_dual.sql`·`application.yml` 수정 금지.** |
| **4. 파일 반영** | 트리거 수신 시 `src/main/resources/YYYYMMDD_price_alerts_<영문설명>_dual.sql` 를 **실제로** `Write`·수정. **slug 갱신** 요청이 있으면 4단계에서 **공개 slug 로테이션**도 함께 수행. 응답에는 **저장된 전체 경로**·행 수·이전→신규 slug 만 적는다(「예정」 금지). |

### 파일 반영 트리거 (4단계 진입)

아래 표현이 있으면 **미리보기 생략 없이** 곧바로 4단계(파일 저장)를 수행한다. *(직전 턴에 미리보기가 없으면 같은 메시지의 종목 블록으로 SQL을 만든 뒤 저장.)*

| 트리거 예 |
|-----------|
| **파일반영** · **파일 반영** · `/dd 파일반영` · `/dd 수정` *(수정안 확정 후)* |
| **저장해줘** · **파일 저장** · **SQL 파일 생성** · **확인** · **OK** |
| **바로 저장** · **확인 없이 파일 생성** · **그대로 저장해줘** |
| **아예 파일로** · **파일로 만들** · **예정 파일명 말고 파일 생성** · **역할 수정 … 파일로** |
| **미리보기 없이** · **바로 파일생성** · **파일생성하고 slug 갱신** · **역할수정 … 바로 파일** |

- **파일 반영만** — Supabase·`price_alerts` / `price_alerts_log` 실제 INSERT **하지 않음**.
- **파일 반영 + 갱신** — 같은 메시지에 **「갱신해줘」** 등이 함께 있을 때만 DB 적재(갱신 모드).
- **파일 반영 + slug 갱신** — **「파일반영하고 slug 갱신」** 등 같이 요청하면 SQL 저장과 slug 로테이션을 한 번에 수행.

### slug 갱신 트리거 (공개 URL 로테이션)

| 트리거 예 |
|-----------|
| **slug 갱신** · **슬러그 갱신** · **공개 slug** · **URL 난수** |
| 파일 반영 문구와 함께: **「파일반영 + slug 갱신」** · **「저장하고 slug 갱신」** |

**수행 내용** (미리보기 2단계 요약에 **slug 변경: 예/아니오** 포함):

1. **신규 slug 생성** — 영문 소문자·숫자 **10자** (`secrets` 등 난수, `[A-Za-z0-9]{10}`).
2. **`src/main/resources/application.yml`** — `app.price-alert-public-slug` 의 **기본값**(`${APP_PRICE_ALERT_PUBLIC_SLUG:…}`)을 신규 slug 로 교체.
3. **이번에 새로 만들거나 이번 `/dd` 로 수정·저장하는 `*_dual.sql` 한 파일만** 상단 `공개 확인:` 주석을 `stocks-ser4.onrender.com/{slug}/new` 로 넣는다. **이미 커밋·저장된 기존 `*_dual.sql` 의 `공개 확인:` 주석은 절대 수정·일괄 동기화하지 않는다** — 과거 배치 파일은 당시 slug 를 그대로 둔다.
4. **미리보기·응답** — 이전 slug → 신규 slug, 메모 원장 URL `https://stocks-ser4.onrender.com/{slug}/new` 를 안내.

**`공개 확인:` 주석 예** (파일마다 slug 가 달라도 정상 — yml·Render 현재 slug 만 최신):

```sql
-- 공개 확인: stocks-ser4.onrender.com/79czxsm2ye/new  (slug 는 application.yml 과 동일)
-- 공개 확인: stocks-ser4.onrender.com/55lk6yvy1x/new  (slug 는 application.yml 과 동일)
```

*(위 두 줄은 서로 다른 시점에 만든 파일 예시. 「과거 파일 주석 = 과거 slug」「신규 파일 주석 = 신규 slug」이며, 기존 파일을 열어 주석만 맞추지 않는다.)*
5. **Supabase·Render** — `APP_PRICE_ALERT_PUBLIC_SLUG` 환경변수를 쓰는 배포는 배포 후 신규 값과 yml 기본값이 **일치**하는지 사용자에게 한 줄로 알림.

- slug 만 갱신(종목 블록 없음)이면 **1~4만** 수행. DB INSERT 없음.
- **미리보기만** 하고 slug 갱신 문구가 없으면 yml·slug **수정 금지**.

**`/dd 수정`**: 기존 `*_dual.sql` 을 고칠 때도 동일 — **수정안을 먼저 보여주고**, **파일 반영 트리거** 후 업데이트.

## 출력 파일 이름

`src/main/resources/YYYYMMDD_price_alerts_<영문설명>_dual.sql`

- **`YYYYMMDD`** (우선순위):
  1. **사용자가 프롬프트에 지정한 “생성·배치 날짜”** — 예: `20260528`, `5/28`, `28일자`, `sql 날짜 20260528` 등. **8자리 `YYYYMMDD`로 정규화**해 파일 prefix에 쓴다. (연도 생략 시 **Asia/Seoul** 기준 현재 연도로 보완)
  2. **지정이 없으면** 오늘이 속한 로컬(**Asia/Seoul**) 달력 날짜 8자리.
- 미리보기·요약(2단계)에 **채택한 `YYYYMMDD`와 근거**(지정 문구 vs 서울 오늘)를 한 줄로 적는다. **파일이 아직 없을 때는 `src/main/resources/…` 경로를 채팅에 쓰지 않는다** — 4단계 저장 후에만 전체 경로를 보고한다.
- **`_dual`** = 한 파일 안에 **`price_alerts` 멱등 블록** + **`price_alerts_log` INSERT 블록** 순서로 둘 다 포함.

파일 상단 주석에 **근거가 된 사용자 원문**과, 가능하면 **파일명 배치일(`YYYYMMDD`)** 을 짧게 남긴다.  
(파일명 날짜 ≠ DB `seoul_log_date` — 로그 UPSERT의 “오늘”은 **SQL 실행 시점** 서울일이다.)

## 블록·작성자 (`price_alerts_log.posted_by` 만)

| posted_by 값 | 규칙 |
|----------------|------|
| **`CHARTBOY`** | ① 줄이 **`✔`·`✔️`(U+2714)·`✔︎`** 로 시작. ② 같은 일일 메모 안 **`✅`·`▶`·`📌`** 로 시작하는 **종목·지수·환율** 줄(예: `✅ 매수타점 체크`·`✅ 지수`·`▶️ 기아`·`📌삼성전자` 블록). |
| **`HYONYHYONY`** | 블록이 **`🌈`(U+1F308)** 무지개로 **시작**하고, 동시에 맨 앞이 ✔ 계열이 **아님**. |

- 줄 맨 앞이 ✔ 이면 **CHARTBOY 우선**(같은 줄에 무지개가 있어도 ✔ 블록).
- `✅`·`▶`·`📌` 는 **차트보이 일일 정리**로 보고 `CHARTBOY` (`HYONYHYONY` 와 혼동 금지).
- 위에 해당 안 하면 해당 줄은 작성자 블록에 넣지 말고 검토 목록 처리.

**`price_alerts.source`** 는 **항상** `'CHARTBOY'` 문자열 고정（앱 규격）.

## SQL 규칙

### 1) `public.price_alerts`

- `INSERT … SELECT … FROM (VALUES …) WHERE NOT EXISTS` — 멱등 키: **`symbol` + `target_price` + `condition`**.
- 컬럼: `market, stock_code, symbol, target_price, condition, label, source`
- **`created_at` 포함 금지**（DB 기본값）.
- `source = 'CHARTBOY'` 고정.
- 손절 등은 원문 근거 있을 때만 **`BELOW`**.
- **`label` 텍스트 보존(이모지 제거)**: 사용자가 적어 준 줄을 **요약·축약·재구성 없이 텍스트만** 넣는다. **이모지(`✅`·`✔`·`✔️`·`▶`·`▶️`·`🌈`·`☀️`·`❤️`·`💛`·`🙏`·`⚠️`·`🔍`·`🔗` 등 모든 Unicode 이모지·변형 선택자)는 모두 제거**하되, 한글·영문·숫자·괄호·`-·/·.·,·!·?` 등 일반 기호는 그대로. (SQL 따옴표만 `''`로 이스케이프) 한 줄에 여러 가격이 있으면 행마다 동일한 텍스트를 라벨에 넣어도 된다.
- **`label` 종목 관련만 적재·갱신**: 해당 행의 **종목(`symbol`) 매수타점·목표가·돌파가·차트 맥락**이 라벨에 실질적으로 담긴 경우에만 `INSERT`·`ON CONFLICT DO UPDATE` 한다. 아래는 **행 자체를 넣지 않음**(기존 DB 행도 라벨만 바꾸지 않음):
  - 일반 투자 원칙·시장 코멘트·영상·채널 안내(「영상을 보셈」「채널 주력주」 등)
  - 갭·전량매도 등 **매도 규칙만** 있고 **그 종목의 구체 목표가·돌파 조건이 없는** 줄(예: 「17프로 갭 상승하면 전량 매도」만)
  - 다른 종목·섹터 이야기, 「매수한 사람이 없나봄」 등 **종목 타점과 무관한** 감상·잔소리
  - 블록 서두 안내(「안 넘으면 안 사면 그만」「가짜돌파」 등) — 종목·가격 없음
  - 가격 숫자가 없고 **그 종목의 매수타점 설명도 없는** 코멘트만 있는 줄

### 2) `public.price_alerts_log`

- `INSERT … VALUES` 다중 행. **`created_at`·`seoul_log_date` 모두 생략**( `price_alerts` 의 `created_at` 과 같음 — DB 기본값·트리거가 KST로 채움). **예외**: 과거 배치일로 묶고 싶을 때만 `seoul_log_date = DATE 'YYYY-MM-DD'` 명시. 선행: `price_alerts_log_seoul_daily_upsert_20260527.sql`, `price_alerts_log_kst_created_at_20260528.sql`.
- 각 행 `posted_by` 는 `CHARTBOY` 또는 `HYONYHYONY`.
- 레거시 DDL: **`WHERE NOT EXISTS` 안 씀**(로그만 적층).
- `uq_price_alerts_log_day_tp` 등 마이그레이션 적용 DB에서는 프로젝트의 **`INSERT … ON CONFLICT … DO UPDATE`** 패턴 허용(`price_alerts_log_seoul_daily_upsert_*.sql` 선행 문서 참고).
- **`target_price` NULL 허용(원장 전용)**: **숫자 목표가가 없어도** 아래면 **log 행을 만든다** (`target_price = NULL`). `price_alerts`(알람)와 달리 **가격 없이 log 만 넣는 경우가 많다**.
  - **종목·지수·환율**에 대한 **차트·매매 맥락**(예: 총쏘는 모양, 5일선 급등, **월봉 양봉 시 매수** 대형주 매매법, 지수 5일·20일선 안내).
  - **가격이 있는 줄**은 숫자를 `target_price` 에 넣고, 같은 종목의 **가격 없는 설명**은 **별도 NULL 행**(같은 `stock_code`·같은 서울일·`posted_by` 당 NULL 은 **1건** — DB `target_price_bucket` sentinel).
  - **지수·환율** 등 KRX 6자리가 없으면 레포·관례 코드 사용(예: `INDEX`+`지수`, `USDKRW`+`원달러환율`). `market = 'KR'`.
- **`label` 텍스트 보존(이모지 제거)**: `price_alerts` 와 동일 규칙 — 텍스트는 **요약·축약·재구성 없이 그대로**, 단 **이모지·변형 선택자는 모두 제거**.
- **`label` 종목 관련만 적재·갱신**: **해당 종목·지수·환율의 타점·가격·차트·매매 맥락**이 라벨에 담긴 경우만 행 생성·UPSERT. `price_alerts` 보다 **log 는 NULL·맥락-only 를 더 넓게 허용**한다. 아래는 **log 에도 넣지 않음**:
  - 일반 투자 원칙·채널 안내만(「영상을 보셈」만 있고 그 종목·지수 조건이 없음)
  - **매도 규칙만**(갭 전량매도 등) — 그 종목의 매수·돌파·차트 맥락 없음
  - 블록 서두·잔소리(종목·지수와 무관)
- `ON CONFLICT … DO UPDATE` 시 `label = EXCLUDED.label` — **종목 관련 라벨인 행만** 갱신.

### 3) 종목 매핑 (**내부 → 인터넷 순, 생략 금지**)

1. **내부 우선**: `src/main/resources` 의 기존 `*price_alert*.sql`·`*_dual.sql`·메모 배치 파일에서 **종목표시코드(주로 KR 6자리)** 검색 (`grep`/파일 검색).
2. **레포에 없으면 반드시 외부 조회**(에이전트는 웹 검색 등으로 실행):  
   공개 시세·공시와 맞는 **종목명 ↔ 표준코드**를 확인한다.  
   예: 네이버 금융·FnGuide·KRX·증권사 시세 페이지 등 **이름이 정확히 일치**하는 종목만 사용.
3. **유사 이름·추측 매핑 금지**(예: 나노 → 나노팀 임의 대입).
4. **동명·지주/자회사 혼동** 등 검색해도 단정 불가능하면 SQL에 넣지 않는다.
5. **그래도 코드·종목을 확정할 수 없을 때만** 응답 **`### 미확정·미매칭 종목`** 에만 적고, 그때는 **「내부·외부 모두 조회했으나 미확정」** 이유를 한 줄로 남긴다.

SQL 파일 상단 주석에는 가능하면 **코드 출처**(레포 파일명 또는 외부 출처 유형)를 짧게 적는다.

## 갱신 모드에서의 적재 구현 메모

- **`price_alerts`**: 기존 멱등과 동일하게 `symbol`·`target_price`·`condition` 기준으로 이미 있으면 SKIP.
- **`price_alerts_log`**: 생성된 VALUES 마다 POST (중복 허용).
- 스크립트에서 직접 실행할 때는 민감정보를 채팅에 노출하지 말 것.
